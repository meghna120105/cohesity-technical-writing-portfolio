# Testing Checklist – Markdown Documentation Checker

## 1. Introduction

Testing is an important part of software development. It helps identify errors and confirms whether a program works as expected.

This document describes the testing process for the Markdown Documentation Checker, a Python-based tool designed to identify common issues in Markdown documentation files.

## 2. Testing Objectives

The main objectives are:

- Verify that Markdown files can be read successfully.
- Check whether empty files are identified.
- Verify whether headings are detected.
- Identify trailing whitespace.
- Check whether broken relative links are detected, if supported.
- Verify that errors are handled properly.
- Confirm that the program generates a readable report.

## 6. Testing Procedure

Follow these steps to test the application:

1. Open the project in Visual Studio Code.
2. Open the integrated terminal.
3. Navigate to the project directory.
4. Run the Python Markdown Checker using the appropriate command.
5. Provide the test Markdown files as input.
6. Observe the output generated by the program.
7. Compare the actual output with the expected result.
8. Record the result in the testing table.

## 7. Error Handling

The program should handle common situations such as:

- Empty input files.
- Missing files.
- Invalid file paths.
- Files that cannot be opened.
- Unsupported input formats.

Errors should be displayed clearly instead of causing unexpected program termination.

## 8. Testing Limitations

The Markdown Checker focuses on basic documentation quality checks.

It does not automatically guarantee:

- Technical accuracy of the written content.
- Correctness of every instruction.
- Grammar and language quality.
- Whether documentation matches the latest software version.

Human review is still necessary to ensure documentation accuracy and usefulness.

## 9. Conclusion

Testing helps ensure that the Markdown Documentation Checker performs its intended functions.

By using structured test cases and recording actual results, developers can identify problems, improve reliability, and maintain better documentation quality.

Regular testing is an important practice in building reliable documentation automation tools.
